# 投稿削除機能 Plan

## Summary

投稿を物理削除せず、`posts.deleted_at` に削除日時を入れる論理削除として実装する。
削除済み投稿は投稿一覧・検索結果から非表示にする。
一覧画面では各投稿右上に三点リーダーメニューを追加し、その中の削除ボタンから削除できるようにする。

## インクリメント1: 論理削除の土台

### 要件

- `posts` テーブルに nullable な `deleted_at` カラムを追加する。
- `Post` エンティティで削除日時を保持できる。
- `Post` は自身を論理削除できる。
- 物理削除は行わない。

### Red TODO

- `Post` のドメインテストを追加する。
  - 新規作成直後の `deletedAt` は `null`。
  - `delete()` 相当の操作後、`deletedAt` に日時が入る。
  - すでに削除済みの投稿を再度削除しても破綻しない。
- Flyway migration 追加後、H2 profile の schema 検証が通ることを確認する。

## インクリメント2: 一覧・検索から削除済みを除外

### 要件

- 通常の投稿一覧では `deleted_at is null` の投稿だけを返す。
- 本文検索でも `deleted_at is null` の投稿だけを返す。
- 最新順の並び順は既存どおり `created_at desc`。
- 既存のタグ表示、いいね数、投稿全体リンクの表示は維持する。

### Red TODO

- Repository テストを追加する。
  - 未削除投稿は一覧に含まれる。
  - 削除済み投稿は一覧に含まれない。
  - 検索条件に一致しても削除済み投稿は検索結果に含まれない。
- Service テストを追加する。
  - `latest()` が削除済みを含まないRepositoryメソッドを呼ぶ。
  - `list(q)` が検索時も削除済み除外メソッドを呼ぶ。

## インクリメント3: 削除ユースケース

### 要件

- `PostService` に投稿ID指定の論理削除処理を追加する。
- 存在する投稿を削除すると `deletedAt` が設定され保存される。
- 存在しない投稿IDは `404 NOT_FOUND` とする。
- 削除後の画面遷移は投稿一覧へリダイレクトする。

### Red TODO

- Service テストを追加する。
  - 存在する投稿IDを削除すると、対象投稿の `deletedAt` が設定される。
  - Repository の物理削除メソッドは呼ばない。
  - 存在しない投稿IDでは `ResponseStatusException(HttpStatus.NOT_FOUND)`。
- Controller テストを追加する。
  - `POST /posts/{id}/delete` でServiceの削除処理を呼ぶ。
  - 正常時は `/posts` にリダイレクトする。
  - CSRFありのPOSTで検証する。

## インクリメント4: 一覧画面の三点リーダーメニュー

### 要件

- 一覧画面の各投稿右上に三点リーダーボタンを表示する。
- 三点リーダー押下で削除メニューを表示する。
- メニュー内の削除ボタンは `POST /posts/{id}/delete` に送信する。
- 投稿全体リンク、タグリンク、いいねボタン等の既存クリック領域を壊さない。
- 既存レイアウトを維持し、メニューは投稿カード上に重ねる。

### Red TODO

- Controller/View テストを追加する。
  - 各投稿に三点リーダーボタンが表示される。
  - 削除フォームの action が `/posts/{id}/delete` になる。
  - 削除フォームにCSRFトークンが含まれる。
  - 既存の `post__detail-link` が残っている。
- CSS/HTML確認項目:
  - 三点リーダーと削除メニューは `post__detail-link` より前面に出る。
  - 投稿右上に配置され、本文・タグ・日付の並びを押し下げない。

## インクリメント5: メニュー開閉のUI挙動

### 要件

- 三点リーダーをクリックすると、その投稿の削除メニューだけが開く。
- 別投稿の三点リーダーをクリックすると、既存の開いているメニューは閉じる。
- メニュー外クリックでメニューを閉じる。
- 削除ボタン押下時はメニュー開閉処理でフォーム送信を妨げない。

### Red TODO

- JSの単体テスト環境が既存にない場合は、まずController/Viewテストと手動確認項目で担保する。
- 実装後の手動確認:
  - 三点リーダークリックで削除メニューが表示される。
  - メニュー外クリックで閉じる。
  - 削除ボタン押下で投稿が一覧から消える。
  - 投稿カード本体クリックでは詳細ページへ遷移する。
  - タグリンククリックではタグページへ遷移する。

## Test Plan

- インクリメントごとにRedを確認してからGreen実装する。
- 最小確認: `./mvnw -B -Ph2 -Dtest=PostRepositoryTest,PostServiceTest,PostControllerTest test`
- 完了確認: `./mvnw -B -Ph2 verify`

## Assumptions

- 削除エンドポイントは `POST /posts/{id}/delete` とする。
- 削除済み投稿の詳細ページ直アクセス制御は今回の必須範囲外とし、一覧非表示を優先する。
- 削除確認ダイアログは今回は追加しない。
- 削除権限・ログインユーザー制御は既存仕様にないため対象外。
